01 · Value of unit tests

Fast feedback creates fearless change.

Unit tests validate small pieces of behavior in isolation. They catch regressions at the cheapest possible moment: while the code is still on your machine.

“Tests are executable documentation: they show what the code promises to do.”

Seconds

to run a focused test and get feedback.

Safer

refactoring with protected behavior.

Clearer

design through visible dependencies.

Fewer

escaped defects in core logic.

02 · Test strategy

Use the testing pyramid

A healthy suite has many fast, focused unit tests; fewer integration tests; and a small number of slower end-to-end checks.

03 · driven development

Types of driven development

💬

BDD

Behavior-driven development: describe behavior in a shared, readable Given–When–Then language.

↻

TDD

Test-driven development: write a failing unit test, make it pass, then refactor.

✓

ATDD

Acceptance-driven development: collaborate on acceptance criteria before implementation begins.

◇

EDD

Example-driven development: use concrete examples or story tests to clarify expected outcomes.

All five approaches shift clarification earlier—before ambiguous requirements become bugs.

05 · Test doubles

Pick the right test double

○

Dummy

Placeholder data required only to satisfy a parameter.

▣

Stub

Returns a prepared value, such as a fake HTTP response.

◉

Spy

Records whether a method was called and with which values.

◆

Mock

A controlled collaborator with expected interactions.

const userApi = { getUser: jasmine.createSpy().and.returnValue(of(fakeUser)) };
expect(userApi.getUser).toHaveBeenCalledWith('42');

06 · Testing patterns

Testing patterns that tell a story

AAA

Arrange · Act · Assert

Set up, invoke one behavior, verify its outcome.

GUARD

Arrange · Assert · Act · Assert

Prove the guard condition, then execute and confirm the change.

BDD

Given · When · Then

Make scenarios readable for product and engineering together. 

it('Given an admin, when save is clicked, then persists the form', () => {
  // Given component.user = admin;  // When component.save();
  // Then expect(api.save).toHaveBeenCalled();
});

07 · A repeatable rhythm

Structure every test with AAA

Prepare the world, perform one behavior, then verify the outcome.

ARRANGE

Create inputs, fixtures, and test doubles.

Call the function or trigger the user action.

ASSERT

Prove behavior

Check the meaningful result.

  // Arrange const cart = { total: 100, discount: 0.2 };
  // Act     const result = calculateTotal(cart);

✂️

10 · Warning signs

Common mistakes to avoid

01

Testing implementation details
Refactors break tests though behavior did not.

02

Over-mocking everything
Tests pass while integrations quietly fail.

03

Flaky async tests
Use fakeAsync, tick, or await settled promises.

04

Chasing 100% coverage
Coverage is a clue, not proof of quality.

05

Giant setup blocks
Hide incidental details with small helpers.

06

Shared mutable state
Reset fixtures so test order never matters.

12 · Angular in practice

Test components from a user's view

1. Configure TestBed

Provide the component, dependencies, and lightweight test doubles.

2. Create & render

Call fixture.detectChanges() to update the DOM.

3. Interact & assert

Click, type, or inspect accessible content as a user would. 

it('shows a welcome message', () => {
  fixture = TestBed.createComponent(WelcomeComponent);
  fixture.componentInstance.name = 'Areeb';
  fixture.detectChanges();
  const text = fixture.nativeElement
    .querySelector('[data-testid="welcome"]').textContent;
  expect(text).toContain('Welcome, Areeb');
});

13 · Test runners

One behavior, two test runners

SHARED APPLICATION CODE 
export function calculateTotal(
  price: number,
  quantity: number,
): number {
  return price * quantity;
}

Behavior: two items priced at 25 should total 50.

Jest 
import { calculateTotal } from './cart';

describe('calculateTotal', () => {
  it('multiplies price and quantity', () => {
    expect(calculateTotal(25, 2)).toBe(50);
  });
});
Jasmine + Karma 
import { calculateTotal } from './cart';

describe('calculateTotal', () => {
  it('multiplies price and quantity', () => {
    expect(calculateTotal(25, 2)).toBe(50);
  });
});
